# 原生 1080p 长程训练首轮

本轮从 Multi step 44 恢复完整模型、优化器、学习率调度与 RNG，追加 1000 步，目标 step 1044。它是三个既有场景上的长程训练首轮，不代表数据规模、收敛或跨视频泛化验收已经完成。

- 网络与损失实现继续使用已有 InfoTok Trainer 和 CHP Stage C；没有增加第二套训练器。
- 每步输入 `[1,3,17,1080,1920]`，内部高度 padding 到 1088；训练不缩放、不裁剪 RGB 输入/输出。
- RGB 与时间损失覆盖完整视频；感知项使用真实 256×256 像素区域。
- 每个块独立抽取 256、512、1024、2048 的接收预算；骨干冻结，保留 RGB 到新模块的梯度。
- checkpoint 每 50 步保存；阶段节点为 100、300、600、1044。阶段退出后才运行评估，避免同一 H100 上训练/评估竞争和显存干扰。
- 三个原始 YUV 只读。训练取各源前约 70%，随后跳过 16 帧，再取 17 帧作为时间留出验证；既有 smoke 使用的前 17 帧均在训练侧。此划分不是跨视频独立测试集。
- 训练窗口在每个场景内随机选择起点，三个场景等频循环。恢复 DataLoader 中途位置不保证逐位重放。
- 验证固定同一组三个 17 帧原生片段、全部四种预算，使用原始 FP32 RGB 参考。第一个训练阶段后同时评估 step 44 基线和 step 100，随后评估各阶段 checkpoint。保留质量负收益。
- BF16 训练延续已验证的路径；既有 BF16 完整/缓存 ID 差异仍未解决，不能因此宣称整数等价。

`prepare_data.py` 只执行数据提取和几何/帧数/像素检查，`run_training.py` 只按 `plan.json` 调用既有训练/评估入口。`commands.jsonl`、`logs/`、`status.json` 保存实际执行状态，`data_split.json` 保存源与产物哈希、精确帧范围及 FFmpeg 命令。大型视频和 checkpoint 继续保存在本机。

实际损失、梯度与显存应读取 `checkpoints/chp_vtok/tokenizer/multi_native17_long_20261115_000518/steps.jsonl` 及本目录日志；本文件没有预填训练成功或质量改善的结论。
